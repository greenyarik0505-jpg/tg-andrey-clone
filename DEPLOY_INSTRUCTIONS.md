# Развёртывание

Запускайте один экземпляр сервиса. Локально `run.py` поднимает FastAPI и Telegram polling. На Render он автоматически регистрирует webhook с проверкой секрета. Задайте команду сборки `pip install -r requirements.txt`, команду запуска `python run.py` и путь проверки `/healthz`. Для другого хостинга с HTTPS укажите `TELEGRAM_WEBHOOK_BASE_URL`.

На Render Free webhook позволяет входящим обновлениям разбудить спящий сервис. При остановке бесплатного сервиса его SQLite сбрасывается, поэтому привязка через кнопку и настройки из панели могут потребовать повторной настройки. Для постоянного хранения задайте `DB_PATH` на постоянном диске. Для локального запуска используйте отдельный токен, пока основной принимает webhook.

## Окружение

- `BOT_TOKEN` — токен бота, передаётся через секреты хостинга.
- `ADMIN_ID` — Telegram ID администратора.
- `BUSINESS_USER_ID` — необязательный Telegram ID владельца. Без него администратор подтверждает подключение через `/business`.
- `WEBAPP_URL` — публичный HTTPS адрес сервиса.
- `DB_PATH` — путь на постоянном диске. Сохраните также резервную копию SQLite.
- `SETTINGS_ENCRYPTION_KEY` — постоянный ключ Fernet. При запуске без него используется файл рядом с БД с суффиксом `.settings.key`. Этот файл нужно сохранять между перезапусками вместе с базой. При переносе действующей БД используйте её прежний ключ.
- Base URL, ID модели и при необходимости ключ своего OpenAI-совместимого провайдера задаются в Mini App или командой `/custom`.

Ключ Fernet для новой базы можно создать командой:

```powershell
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

Адрес провайдера задаётся прямо в Mini App. Разрешены любые HTTP(S) домены, включая адреса с нестандартным портом. Можно указать Base URL или полный адрес `/chat/completions`. При смене origin сохранённый кастомный ключ очищается, если одновременно не введён новый.

## Обновление

Остановите старый процесс, сохраните резервную копию БД и разверните новую версию. Настройки кастомного провайдера сохраняются при сохранении базы. Если раньше использовался встроенный пресет, настройте свой провайдер. Новые чаты, разрешённые в Telegram, получают автоответы по умолчанию. История старого формата остаётся в базе. Для другого владельца используйте отдельный `DB_PATH`.

Если старая панель была доступна по сети, перевыпустите ключи провайдеров, которые были сохранены через неё. Старая версия возвращала их через API без входа.

## Проверка после запуска

Откройте `/healthz` и убедитесь, что сервис возвращает `200`. Запрос к `/api/settings` без авторизации должен вернуть `401`. Из Telegram откройте Mini App через `/start`, выполните пробную генерацию и включите автоответ для одного выбранного чата. Проверьте отметку в ответе и поведение паузы.
